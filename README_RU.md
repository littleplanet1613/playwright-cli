# Playwright CLI — русская инструкция для Codex

Это форк официального `microsoft/playwright-cli`, который мы используем как браузерный инструмент для Codex.

Главная задача: дать coding-agent возможность **самому проверить веб-приложение после изменений** — открыть страницу, нажать кнопки, заполнить поля, изменить размер окна, сделать снимок структуры страницы, скриншот или PDF и воспроизвести пользовательский сценарий.

## Почему CLI, а не Playwright MCP

Для нашего сценария с Codex предпочтительнее CLI + Skills:

- меньше расходуется контекст и токены;
- агент вызывает короткие команды вместо загрузки больших схем MCP;
- удобнее сочетать с большим кодовым репозиторием;
- можно использовать как отдельный инструмент у `tester`-агента;
- браузер можно открыть в видимом режиме и наблюдать работу агента.

MCP имеет смысл для длинных автономных браузерных сессий с постоянным состоянием и глубокой интроспекцией страницы. Для обычной разработки и проверки интерфейса CLI проще и экономнее.

## Что умеет

Основные возможности:

- открыть сайт или локальное приложение;
- переходить по страницам;
- находить элементы;
- нажимать кнопки и ссылки;
- вводить текст;
- работать с чекбоксами, выпадающими списками и формами;
- загружать файлы;
- менять размер окна для проверки адаптивности;
- делать скриншоты;
- сохранять страницу в PDF;
- работать с несколькими вкладками;
- сохранять и загружать состояние браузера;
- показывать активные браузерные сессии через визуальный dashboard.

## Требования

- Node.js 18 или новее;
- npm;
- Codex или другой coding-agent;
- проект, в котором нужно проверять веб-интерфейс.

## Установка программы

```powershell
npm install -g @playwright/cli@latest
playwright-cli --help
```

## Установка Skill для Codex

Важный момент: для Codex нам нужен формат `.agents/skills`.

Открой терминал **в корне конкретного проекта**, который Codex будет разрабатывать и проверять, и выполни:

```powershell
playwright-cli install --skills=agents
```

После этого в проекте появится:

```text
.agents/
└── skills/
    └── playwright-cli/
        └── SKILL.md
```

То есть Playwright Skill лучше подключать только к тем проектам, где действительно нужен браузер.

## Простейший пример

Открыть сайт в видимом браузере:

```powershell
playwright-cli open https://example.com --headed
```

Получить структуру страницы и ссылки на элементы:

```powershell
playwright-cli snapshot
```

Сделать скриншот:

```powershell
playwright-cli screenshot --filename=check.png
```

Закрыть браузер:

```powershell
playwright-cli close
```

## Как будем использовать с Codex

Обычно вручную команды вводить не потребуется. Можно поставить задачу обычным языком:

```text
После правки запусти приложение и через playwright-cli проверь основной пользовательский сценарий.
Проверь desktop и узкий мобильный viewport.
Сохрани скриншоты только если они помогают подтвердить результат или показать ошибку.
```

Для локального приложения:

```text
Проверь интерфейс на localhost через playwright-cli.
Не ограничивайся тем, что сборка прошла: реально открой страницу и проверь кнопки и формы.
```


## Безопасность

Playwright управляет реальным браузером, поэтому считаем клики и отправку форм реальными действиями.

По умолчанию:

- тестируем localhost, staging или специально выделенное тестовое окружение;
- не совершаем покупки и платежи;
- не подтверждаем удаление данных;
- не публикуем материалы;
- не отправляем массовые сообщения;
- не меняем production-настройки;
- не используем сохранённую авторизацию для чувствительных сервисов без явной необходимости.

Если проверка упирается в труднообратимое действие, агент должен остановиться и запросить разрешение пользователя.

## Обновление

Обновить CLI:

```powershell
npm install -g @playwright/cli@latest
```

После обновления в каждом проекте, где установлен skill, полезно повторить:

```powershell
playwright-cli install --skills=agents
```

Так локальный `SKILL.md` будет соответствовать установленной версии инструмента.
